# Конфигурация окружения

Для локального запуска и сборки каркаса переменные окружения не требуются.
`.env.example` содержит закомментированный пример runtime-настроек adapter-node.

## Локальная разработка

```sh
npm ci
npm run dev
```

При необходимости локальных переменных создайте `.env` по образцу `.env.example`.
Файл `.env` исключён из Git.

## Adapter Node

Production-сервер `@sveltejs/adapter-node` понимает стандартные runtime-переменные:

| Переменная | Назначение |
| --- | --- |
| `HOST` | интерфейс, на котором слушает Node-сервер |
| `PORT` | порт Node-сервера |
| `ORIGIN` | внешний origin приложения |
| `NODE_ENV` | режим Node-процесса |

Пример production-окружения:

```dotenv
NODE_ENV=production
HOST=0.0.0.0
PORT=5173
ORIGIN=http://localhost:5173
```

Укажите фактический внешний origin. При запуске через systemd Node получает
переменные из `.env` с помощью `--env-file`; конкретный пример приведён в
[systemd-инструкции](../deployment/systemd.md).

Изменение runtime-настроек требует перезапуска Node-процесса.

## Переменные новых модулей

Способ чтения переменной определяется её владельцем в коде. Настройки,
импортируемые через `$env/static/public` или `$env/static/private`, фиксируются
при сборке; после их изменения приложение нужно пересобрать. Runtime-настройки
могут читаться через `$env/dynamic/private` на сервере.

Не добавляйте префикс `PUBLIC_` к секретам и не передавайте private-настройки
через page data, клиентские компоненты или публичные endpoint responses.

## Источник истины

- проектные переменные и примеры — `.env.example`;
- способ чтения переменной — использующий её модуль;
- runtime-настройки adapter-node — deployment-конфигурация окружения.

Документация объясняет назначение настроек, но не задаёт секретные или
машинно-зависимые значения.
